# Read a handoff without filling the context

A handoff is often 40-80 KB, and most of it is an exact command log the app generated. Reading it whole at the start of a session spends a large share of the context before any work starts. Read the sections that carry state, and look up anything else only when the task needs it.

## Steps
1. Find it: the path the user named; else the newest file in `handoffs/` (`list_files` with a glob such as `handoffs/*.md`; the date in the name decides, and `-v3` is newer than `-v2`). Handoffs the app writes at each compaction are in `handoffs/auto/`.
2. Map it before reading: a handoff the app wrote starts with a **Contents** list giving the line of each section, so read its first 30 lines. Otherwise `outline_file` (if offered) or `search_files` with the regex `^#{1,3} ` on that file gives each heading's line.
3. Read only these sections, each with `read_file` and `start_line` (whatever their numbering or exact titles):
   - the header and status paragraph before the first section;
   - goal and current status; open tasks or OPEN ITEMS; NEXT ACTIONS or next steps;
   - user requirements, preferences and constraints; key facts and gotchas;
   - decisions and reasons; errors or issues with their root cause and fix;
   - WORK DONE or work done in detail; code and file changes, or files read and changed (the paths and what changed: stop reading a long code block after its first lines).
4. Skip: "Commands run", "Commands and results", "Activity log (generated by the app)", "App record (generated by the app)", "Useful commands (runbook)" and "FILES & RESOURCES USED". They are logs and lists: when the task needs one exact command, path or output, `search_files` the handoff for a keyword and read only the lines around the match.
5. Referenced files: do not open every file a handoff lists. Read another handoff or document only when the handoff tells the reader to (for example "read v11 section 2"), and then only that section.
6. Several handoffs: the newest supersedes older ones. Read an older one only for a section the newest one points to, or, when writing a handoff of a whole compacted conversation, for that conversation's auto handoffs (oldest first, the same sections).

Never read a section twice, and batch independent reads into one response.

## Then
Reply with a short orientation (5-10 lines): the goal, the current state, the open items, the next actions, and any question the handoff leaves for the user. Do not start the next actions unless the user asked you to continue the work.
